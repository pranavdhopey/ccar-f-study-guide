The Agentic Loop

CCAR-F  ·  Domain 1: Agentic Architecture  ·  Task 1.1  ·  27% of exam is Domain 1

1What is it? (in plain words)

  • Claude alone: 1 question → 1 answer. It can only talk.
  • To do things (look up an order) it needs tools = functions in my code.
  • Claude never runs a tool. It only asks for one. My code runs it and sends the result back.
  • The code that keeps repeating this = the agentic loop. It is normal code (control flow), not a prompt trick, not a retry loop.
Agent =
Claude
+ Tools
+ Loop code

2The 4 steps (repeat until done)

tool_use = Claude wants a tool → keep going
end_turn = Claude is finished → stop
Step 3 is where loops break: if I forget to append the tool result, the API has no memory. Claude never sees it!

3Golden rule

stop_reason is the ONLY reliable signal for loop control.
It is deterministic and unambiguous.

4Who picks the tool?

Model-driven (default, exam-favoured)
Claude reads the task and chooses tools → handles surprises, chains tools in orders nobody planned.
Fixed decision tree (developer hard-codes it)
Only when rules must be followed: money, security, regulations. Code enforces it (see 1.4).

53 anti-patterns (never the main stop signal)

  • Parse the words. "I'm done", "task complete". Language is vague: "I finished file 1" may mean "file 2 next".
  • Iteration cap as the boss. "Stop after 10 loops". Cuts off real work or wastes loops.
  • Text = finished. content[0].type == "text". Claude often sends text and a tool call together.
Premature-exit bug: Claude says "Let me look up your order" + a tool_use block. Code sees text first, thinks finished, returns half an answer.
Fix: check stop_reason, never the content type. Continue on tool_use, stop on end_turn.

6Exam traps

  • Caps are a safety net for runaway agents (e.g. 20), never the fix for stopping too early.
  • Do not drop tool results or swap history for a summary to save tokens. Shrink what the tool returns instead.
  • Right answer pattern: continue on tool_use, end on end_turn, reject all 3 anti-patterns.
